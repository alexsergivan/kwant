Multiple Claude, Codex and Grok accounts

Use every account you have. A space can hold several accounts per engine, for example a work Claude subscription, a personal one and an API key. When one runs out of usage, kwant moves the turn to the next account in your order, on any engine.

Account profiles

A profile is one account for an engine, for example a work Claude subscription and a personal one. Every engine starts with a This machine profile, which uses the CLI's own login, or the key from Settings or the environment.

KindRuns withSigned in by
systemThe CLI's default config folder, or the Settings or environment keyWhatever you did on the host
cli_homeIts own config folder; host credential variables are removedThe in-app sign-in, or your own folder
api_keyThe provider's API, with only the profile's keyThe key you paste
custom_apiYour own server, with its key if it has oneA check of the server's model list

Keys are write-only: no API response ever contains one, only whether it's set.

Signing in a CLI profile

kwant runs the CLI's own login with the profile's folder. For Claude, open the link and paste the code shown back into kwant. For Codex and Grok, open the link and enter the code. A sign-in expires after 10 minutes.

Order to use

Settings → This space → Accounts starts with Order to use: every account in the space, across Claude, Codex, Grok and Custom API, in one list. When one runs out, kwant bots move to the next that still works, in this order. Use the arrows, or drag a row, to move an account earlier or later. Each row shows its engine and whether it's Ready or out until its reset, for example "Out until 03:00". Accounts that are signed out or not installed are listed below, under Not in the order, with no number or arrows. They join the order at the bottom once they're ready.

Failover

A turn starts on its bot's account: the one it's pinned to, or its engine's default. When that account is out of usage or signed out, and nothing has been shown or done yet in the turn, kwant moves the turn to the next account in the order that still works, on any engine, up to 6 attempts. An account known to be out is skipped until its reset, and bots go back to it after the reset on their own.

  • The same kind of model. On another engine, the turn uses that engine's model of the same tier. A Custom API account uses a model its server offers.
  • One quiet line. Under the bot's name, the reply says once per outage what happened, for example "Claude is out until 03:00 · answered on Codex (GPT-6.1)".
  • A limit message is never the reply. A line like "You've hit your session limit · resets 3am (Europe/Berlin)" counts as the account running out, with its reset time. It's never saved as the bot's answer.
  • When every account is out, the message waits for the earliest reset, and the chat says "Every model is out until 03:00 CET; I'll answer then." The time is in your saved time zone, with its abbreviation.
  • Overloads and rate limits are retried, not failed over.

Turn failover off for a bot to keep it on its own account.

Pinning a bot

In a bot's settings, pick the account it should use, or leave it on the engine's default. Clear Switch to the engine's next account when this one runs out of usage or is signed out to keep the bot on its account.

Custom API accounts

Add an account with the server's base URL and, if needed, a key. kwant checks the server's model list when you save it and shows whether it's ready, unreachable or rejected the key. A space can have several custom accounts, and they belong to that space only.

  • Paste the base URL with or without /chat/completions or /messages: kwant trims it to the API root.
  • MCP tools are offered on OpenAI-chat servers. Anthropic-Messages servers run without tools and say so.
  • Custom API never falls back to the host's accounts.
Keep a space off this machine. Each space has a Use This machine switch. Turn it off to keep the space on its own accounts: its bots never fall back to the CLIs signed in on the computer running kwant.
