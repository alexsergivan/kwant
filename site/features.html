New in 0.7.4

Use kwant from your coding agent, and a daily spending stop

Claude Code, Codex or Cursor can hand work to your bots and get the reply back. A daily stop caps what all bots spend. Dev mode reviews merge requests on GitLab, Gitea and Forgejo, and "Ask only when risky" now asks before a bot adds a new package.

Use kwant from your coding agent

Claude Code, Codex, Cursor and other MCP clients can ask your bots for work and get the reply back where you're coding. Each connection has its own token, shown once, reaches only the spaces and bots you pick, and is revoked at once. The agent is never you: it can't approve anything, and its token opens nothing else in kwant. Connect one

A daily spending stop

Settings → All spaces → Usage can cap what all bots together use in a day, in tokens, dollars or both, right next to today's use. Both are off until you set them. Past the cap no new work starts, from a chat, a hand-off, a routine, a mission or a coding agent; work already running finishes. How the stop works

Reviews on GitLab, Gitea and Forgejo

Connect a GitLab, Gitea, Forgejo or Codeberg server and its merge requests and pull requests get review cards with their CI, like GitHub's. Posting a review back is still GitHub only, and the card says so. Dev mode on other forges

A new package asks first

Under Ask only when risky, a bot adding a package the project doesn't list yet now shows a card first, because the package's code runs on your computer: npm install left-pad, cargo add, uv add, go get and the like. A plain npm install of what the project already lists still runs. How package asks work

Connected in a minute

Name the connection, pick its spaces and bots, and copy the one-line setup for Claude Code, Codex or Cursor. Its first ask shows up under Recent activity, and the bot's thread is in kwant for you to read along. Each connection can make 60 asks an hour, and its work counts toward the spending stop.

When the stop is reached

A chat gets one notice a day with Continue today or Change the limit. Routines, missions and AutoFix skip without counting as failures, Needs you shows one item, and the first stop each day sends one notification. The day follows your time zone.

Add GitLab, Gitea or Forgejo

In Loose ends, Add a source takes the server's address and a token. kwant asks the server which forge it runs, and asks you only when it can't tell. A repo row on the Dev desk with no connection yet has a Connect GitLab (or Gitea, or Forgejo) button that opens the same form in place.

A card for every pushed branch

A repo with no forge, or no token for it, still gets reviews: each pushed branch that's ahead of the watched one gets a review card, with no CI and no Post. The repo list shows where each repo lives.

GitHub Enterprise, as you paste it

Paste your server's address as it is, github.yourcompany.com or yourcompany.ghe.com, and kwant finds the API itself. Repos on yourcompany.ghe.com now match their connection in Dev mode. Leave the field empty for github.com.

  • Bots don't paste your keys back

    Give a bot a key, password or token and it still does what you asked with it, but its reply names it, or shows its last 4 characters, instead of writing it out.

  • Same checks for every forge

    Requests to GitLab, Gitea and Forgejo take the same address checks as git fetches, and never follow redirects.

Videos play in the chat

New in 0.7.2

Dev mode watches every team's repo

A space no longer has one watched repo. Each team brings its own, up to 10 per space, and Dev mode watches all of them. A ? beside the switch says what Dev mode does, and the switch has a new look. New to Dev mode? Start with 0.7, further down.

Every team's repo

Dev mode finds each team's repo: its repo link, or its folder when that folder is a git checkout. Each repo is checked on its own. One that loses its GitHub connection or can't be found shows on its own row with one fix, Connect GitHub, Link a repo or Remove, and the others keep going. How it finds repos

What Dev mode does, in the app

Dev mode and Approvals have their own rows under the space's name. The ? beside Dev mode says in plain words what it does: what landed, reviews and the production floor. It's a popover on the desktop and a sheet on the phone, with a link to the guide.

A repo on every card, and a filter

With more than one repo, every card says which repo it's from, and What landed and Reviews filter by repo. The production floor, the command guards, approvals and the daily review limit stay the same for the whole space.

A new switch

A track with a knob and the word Off, On or Off?. The first press to turn Dev mode off shows Off?, and a second press within 5 seconds turns it off. Escape or waiting keeps it on. The Approvals row shows the approval mode, and the amber Dev mode pill is gone.

Link a repo, and it's watched

A team with no repo shows as one quiet line on the Dev desk. Press Link a repo, type the repo, and its row reads Watching. Linking a repo never turns Dev mode on by itself.

  • The badge and the roll-up keep their own seen time

    Opening the Dev desk clears the new-reviews badge, from a link too, and Mark seen starts the "since you last looked" roll-up over. Before, opening the desk emptied the roll-up as well.

  • GitLab, Gitea and other git hosts in 0.7.3

    Until then the desk names them, and the production floor and the command guards work for them.

  • Don't go back to 0.7.1

    Once 0.7.2 runs, 0.7.1 stops making new Dev mode cards. Nothing is lost, and updating again fixes it.

Post to GitHub

A review card goes onto its pull request as one review comment, posted as you and pinned to the commit that was reviewed. Findings go on their lines. kwant never approves, requests changes or merges, a bot can't post, and secrets are never posted. How posting works

No setup dialog. kwant looks at the space's teams, their repo links and their folders, on your machine with no network. A note says what it found, with Undo. On, and the last five merges written up

One press on the switch. kwant names the repo it found, reads the last five merges and writes a plain-words card for each.

New in 0.6.11

Answer with a tap, reply to a message, solve the human check

Every finished bot message has 👍, 👎 and Reply next to Copy markdown. When a site asks if the bot is human, the check comes to you.

👍 and 👎 answer a question

When the bot's newest message asks you something, 👍 means Yes, go ahead and 👎 means No (the words show on hover), and picking one answers it. Anywhere else a reaction is feedback the bot reads on its next turn; after a 👎 it says what it would change. A 👍 never approves an approval card, a payment or a decision card.

Reply to a message

Reply puts the message in a "Replying to" chip in the box, and the bot is told which message you mean. Your message shows a one-line quote; click it to jump to the original. In a room, the reply goes to the bot that wrote it unless you @mention another.

Every CAPTCHA comes to you

A Human check needed card comes up in the chat (or thread) where the check stopped the bot: a page from a link you sent, the bot's own web tools or a browser step. You solve it, and the bot carries on by itself. kwant never solves or bypasses a check itself.

Solve it in the bot's browser

Solve it opens the page in the browser panel. While you're solving it, the bot stays off that browser.

Yes, go ahead, and the bot carries on

Lead asks whether to publish the release notes. One tap answers it, and the reply comes back with nothing typed.

Know when a bot needs you, and take over its browser

A pill tells you when a bot is waiting on you in another chat, wherever you are. When a bot needs you to sign in, you take over its browser, sign in yourself and hand it back.

A pill when a bot needs you

An approval, a question or a sign-in in another chat slides in at the top for a few seconds. Click it to go there. The tab title counts what's waiting, like (2).

Bots ask you to sign in

Ask a bot to use one of your accounts and it posts a sign-in card. Open browser takes you to the page, and Done, I'm signed in lets the bot look again. It never asks for a password in chat.

Take over the page

The bot's page opens on a large stage at its real size. Click, type and scroll as in your own browser, then Hand back. The bot waits while you're in control.

See what a bot is doing

A line above the message box says what the bot is using right now and for how long.

A pill, then one click to the approval

You're reading one channel when TechLead needs your OK in another. The pill shows who and what for a few seconds.

On the Mac app and on Linux

The Mac app shows the same pill under its menu-bar icon, in light and dark mode, and two at once become one. On Linux, the tray icon gets a badge and you get a desktop notification.

  • A count in the tab title

  • On your phone too

New in 0.6.5

Replies you can sort, goals that stay true, models that cover for each other

A table or list in a reply becomes a card, goals keep what matters working, and when one account runs out the next one answers. It's all on from the start, and so is everything that used to wait for a switch.

Smart Results: replies you can sort and copy

A table or list in a bot's reply shows as a comparison, chart, key numbers, findings or a checklist. Every value is copied from the reply, never worked out, and the line under it says where it came from. Show as text brings back the words, and Copy data gives Markdown, CSV or JSON.

Ask about one row

On a comparison, Ask about this puts a line about that row into your message box, and nothing is sent until you send it. Cards are worked out once, without a model call, and anything kwant can't draw stays as text.

Goals: what should stay true

Say it in a sentence and a bot drafts the checks: a page answers, a command succeeds, a file exists. One quiet line while all is OK. When a goal breaks, a bot looks into it and you get one decision: Fix it, Not now or Always fix this goal. Nothing runs until you create or approve a goal.

Automatic model failover

Put every account in one order under Settings → This space → Accounts → Order to use: Claude, Codex, Grok and Custom API. When one runs out, bots move to the next that still works, the chat says so in one quiet line, and they go back after the reset.

  • On from the start

    AutoFix, the Auditor, Flight School, Skill Foundry, suggested routines and the Truth Ledger now run without setup, also on installs that never changed them. A choice you saved is kept, and the caps stay: a 25% recovery budget for AutoFix, 5 audits and 2 routine suggestions a day.

  • New bots start at Act

    Flight School keeps a scorecard for every bot, and Act adds no approval cards of its own. Pick a lower start for new bots, or a lower tier for one bot, in Settings. Payments always ask.

  • A limit message is never the reply

    A line like "You've hit your session limit · resets 3am" is no longer saved as a bot's answer. kwant reads the reset time and moves the turn to the next account.

  • When every account is out

    The message waits for the earliest reset, and the chat says "Every model is out until 03:00; I'll answer then." A bot with failover off stays on its own account.

  • The same kind of model

    On another engine, the turn uses that engine's model of the same tier. Rate limits and overloads are retried, not failed over, and a turn never switches after a bot has shown or done something.

New in 0.6.4 · Who answers

The right bot answers, says why, and learns when it's wrong

In a channel, kwant picks the bot that fits your message and shows you why. Wrong bot? sends it on and teaches routing. Each bot also gets rules from you: what it's good for, what it's not for, and which sites its browser may open.

Every answer says why, and Wrong bot? learns

A reason line under the answer says why that bot took it. Wrong bot? lists the other bots: pick one and your message goes to it, and messages like it in that space go there from now on. Only you can make a correction.

A close call asks you

When no bot clearly fits and two come close, a card asks who should answer, with both bots and Answer generally. Nothing is answered until you choose, and only you can choose. The bot you pick teaches routing too.

Good for and Not for

List what a bot should take and what it shouldn't, on the New kwant bot form or in its settings. Good for counts like its title when kwant picks. Not for keeps it out of picks by words, by what you taught and by small talk. Naming or @mentioning a bot still reaches it.

Browser sites for each bot

Allow only some sites, block others, or keep a bot's browser off your local network. kwant checks each page the bot opens, follows or is sent to, and blocked wins over allowed. Only you set them: a change sent with a bot's key is refused.

  • The Concierge in #general

    When no bot fits a message in #general, kwant adds a Concierge, a generalist, to answer it, with an undo. Remove it and those messages go to the channel lead instead.

  • Hand-back

    A bot picked by the words in your message can hand it back once, with a reason. The next bot that fits takes it, or else the Concierge or the lead, and the reason line says so.

  • Laya's second opinion

    Laya reads your bots' titles and adds weight to a pick it agrees with. It never picks alone, and when it's offline the reason line says the pick was a keyword match.

New in 0.6 · Mission Control

Freedom bots earn, facts they agree on, results you can count

Bots ask for more freedom when their record earns it, conflicting facts wait for you, and the board counts verified results and what each one cost. Since 0.6.5, Flight School and the Truth Ledger are on from the start.

Bots ask, only you grant

A bot whose scorecard qualifies can ask for a higher tier for one kind of work. The request waits under Needs you with its scorecard, and you Grant or Decline it. A bot can never grant itself, revoking is still one tap, and payments always ask.

A scorecard per kind of work

Verified tasks, first-try rate and what a bot still needs for the next tier, over the last 30 days. The same request and scorecards show in the bot's settings.

Truth Ledger: conflicts wait for you

When two facts disagree, both are flagged Disputed until you pick Keep this one or Not a conflict. Facts show their evidence and the tasks that rely on them. On from 0.6.5, and with it off bots see exactly what they saw in 0.5.

Insights: verified per week, and the cost

Verified results per active week over the last 8 weeks, and the cost of each one, failed runs included. A missing cost is said plainly, never shown as $0.

New in 0.5 · Browser & status

Bots that show their work

Web facts come with a link to the exact quote, the browser tells a bot what each step changed, and every bot's avatar says what it's doing.

  • Bots bring receipts

    A bot passes the exact words it read, and kwant checks they are on the page once, word for word. It gets back the quote, its address and a link that opens the page with the quote highlighted. A quote that isn't on the page, or is on it more than once, is refused with the reason, so a bot can't make one up. No model calls.

  • Sees what each click changed

    After every click, key or typing, the bot gets one line saying what changed: the page it went to, or the new and gone lines. If its last 3 steps changed nothing, it is told to stop and try something else.

  • Clicks by number, never through a banner

    The page a bot reads lists its buttons, links and fields as numbered refs. A click by ref hits exactly that control. If a cookie banner or dialog covers it, nothing is clicked and the bot gets a fresh list with the reason.

  • No re-reading the same page

    Reading an unchanged page again gives a one-line "unchanged". On a page with more than 40 controls, the bot can say what it looks for and the matches are listed first.

  • Asks before paying, also behind "Continue"

    Before a bot clicks, kwant reads the page: the button the click would really hit, card number fields, a payment provider's card frame and forms that post to a checkout. Any of these gets the payment card, in every approval mode.

  • Status dots

    The dot on each bot's avatar says what it's doing: green Available, a pulsing Working dot, amber Needs you, a hollow Queued ring or grey Can't run. Hovering or a screen reader gives the status in words.

New in 0.5 · Automation Discovery

Routines that suggest themselves

kwant notices tasks you ask for on a rhythm and offers a routine for them. Nothing is made until you press Accept. On from 0.6.5.

  • Suggested routines

    On from 0.6.5, under "Suggest routines from repeated tasks" in Settings → All spaces → Mission board. kwant looks at the board tasks you made over the last 120 days and finds ones you ask for daily, on weekdays, weekly or monthly. At most 2 new suggestions a day, each with its schedule, first run, checks and the tasks it came from.

  • Accept or dismiss

    Accept opens the routine form so you can change it first. Dismiss hides a suggestion for 30 days. Routines made this way carry a "Suggested for you" badge.

  • Routines know what a good run is

    A routine can carry a Flight School class, a description of a good result and checks. A run that passes its checks is verified on its own. Only you set the class and the checks.

  • Truth Ledger

    A preview in 0.5. Since 0.6, with it on, and it's on from 0.6.5, bots read their notes from the shared list of facts. Notes a bot wrote after reading a web page, a file or another tool stay Unconfirmed until you confirm them, and conflicting facts wait for you. Truth Ledger docs.

  • A star, asked once

    After real use, a small card asks for a GitHub star, with Maybe later and Don't ask again. It never shows on first run or while a bot needs you, and nothing is sent anywhere.

Hand-offs & review

Work handed on, checked and seen

Teammates pass work along on their own, the bot that handed it out checks the result, and a bot can look at a page instead of only reading it.

  • The lead reviews hand-offs

    When a teammate finishes, the bot that handed out the work reviews it: a pass makes the card Verified, a fail sends it back with the reason. It gets one reminder, then the card says "Waiting for <lead> to review". A bot still can't approve its own card.

  • Notices don't wait in Review

    A one-way hand-off nobody is asked about is shown as Closed, "Notice, no review needed", never as Verified.

  • @mentions in a result hand work on

    When QA's result says "@Frontend could switch the header", Frontend gets that task even if the lead doesn't pass it on. The lead hears back once, with every result.

  • One @mention picks who answers

    "@Frontend why didn't you answer QA" goes to Frontend, even though it names QA. Two @mentions still go to the lead.

  • Bots see the page

    A browser_screenshot tool hands Claude and Codex bots a real picture of the page, at a width they choose (390 for a phone, 1280 for a desktop), so a designer can check layout, colours and spacing.

  • No token limits by default

    Tasks, missions and hand-offs no longer stop at a hidden token budget. Set one in Settings → All spaces → Usage if you want it. Hand-off caps (4 per bot, 16 per request) still stop loops, with a Continue button.

Performance & audits

Learn from the work that's already done

See which bot and model does each kind of work well, have a second bot challenge important work, and turn work done well into skills. All of it needs the Mission board, and since 0.6.5 the Auditor and Skill Foundry are on from the start.

Who does each kind of work well

Verified rates by bot or by model over the last 30 days, 90 days or all time. Report-only: it never decides who gets work.

Open risks on the task

When the Auditor is on, a second bot's risks sit on the task with their evidence and the owner's answer. You resolve or dismiss each one.

  • Performance (report-only)

    Under the board, per kind of work and bot or model: tasks finished, the verified rate with its likely range, median time and tokens, cost per task and how often you stepped in. Groups with fewer than 5 tasks say "few tasks". It never changes who gets work.

  • Swarm Auditor

    An important task, or one no outside check will judge, gets one challenge when it reaches review: a teammate from outside the lead's loop lists risks with evidence, and the owner answers once. An audit never verifies, fails or moves a task. Up to 5 a day by default, on a fast, cheap model unless you pick another.

  • Open risks

    What an audit leaves unresolved is listed on the task, with its evidence and the owner's answer, until you Resolve or Dismiss it. Board cards count the open risks.

  • Skill Foundry

    When a bot has 3 or more verified tasks of one kind of work in 60 days, 70% of them verified, it drafts a skill from them. Each draft is replayed as a dry run on up to 3 of those tasks in a scratch copy, and waits in the Skills tab for you to approve, edit or reject. Versions can be rolled back. On from 0.6.5, and switched off through the API.

Mission board

Work your bots can prove they finished

One board for every task your bots take on. A task counts as Verified only when a check passes, never on a bot's word.

One board, five columns

Missions, hand-offs, routine runs and loose ends you take on, from Ready to Verified. Needs you collects every question, approval and failure waiting on you.

Verified · 1/1

Verified outcomes, with evidence

A check proves it: a command that passes, a page that answers, a file that holds the right text, a teammate's review or your OK. Each task keeps the receipt.

Checkpoints and restore

kwant snapshots a task's folder before and after every run. Preview a checkpoint and restore it: only that task's files go back, and you can undo the restore.

AutoFix

A failed task says why and what to fix. AutoFix retries what is safe to retry, within a budget, and asks first if you prefer. Sign-in problems and denied actions always come back to you.

Fails, retries, Verified

A load-test report misses its p95 latency, so the check fails. AutoFix runs it again with what the check said, and the task ends Verified.

How AutoFix works →

  • No marking its own homework

  • Insights

  • On a phone

Flight School

Freedom a bot earns, one kind of work at a time

Give each bot a tier per kind of work: Observe, Sandbox or Act. A tier only adds approval cards, and payments always ask.

A Sandbox bot asks first

QA works at Sandbox on releases. It may change files in its task folder, but a build command asks, and the card says why. You allow it once, and the task ends Verified.

What Sandbox asks about →

Tiers per bot and per kind of work

Sandbox for everything, Observe for deploys, Act for release notes. Revoke lowers a tier in one click, from the bot's next action.

On from the start, at Act

Safety & control

Autonomy you control

Bots get on with ordinary work. You choose which steps ask first, and every change can be undone.

Hiring you approve

Bots can propose a new teammate. Accept once, always, or deny. Each space sets its rule.

Saved passwords

Website logins in kwant's encrypted vault or your own Bitwarden. With approvals off, kwant asks you once whether to keep them on this server or move them to Bitwarden.

  • Approval cards

    Allow once, Always allow or Deny, with the exact command or arguments.

  • Three approval modes

    Ask only when risky, the default for new spaces. Or ask before running commands, or don't ask. Per space, and per bot.

  • Changes with an Undo

    Bots create routines, channels and bots when asked, each with an Undo. Deletions ask first.

  • Things bots can't change

    Keys and secrets, sign-ins, approval rules and computer mode stay yours.

  • Sign in your phone with a QR code

    Settings → All spaces → Signed-in devices shows a one-time QR code for a new phone or browser, and lists your signed-in browsers with Sign out.

  • Approve a new device

    A new browser can ask for access with a 10-minute code. Your signed-in browsers show the code, the browser and its IP, with Approve or Deny.

  • kwant's secrets are off limits

    In every mode, tool calls that name kwant's own secret files are refused.

  • Safe imports

    Imported bots arrive with no tools and no keys. Their skills wait for approval and their routines start paused.

Usage

For API-key and custom-API bots, a Usage tab breaks tokens down by purpose, cache and call.

  • One binary

    kwnt has the web app and an SQLite database built in. No Node.js at runtime.

  • Laptop or VPS

    Nothing to sign in to locally. On a server, open the link it prints once. Docker Compose and a systemd unit are included.

  • Any CLI or API

    The claude, codex or grok CLI, or Anthropic, OpenAI or xAI keys.

  • MCP tools

    Add any MCP server and pick which bots can use it. OAuth for servers that need a sign-in.

  • Composio, optional

    Under Settings → This space → Connections, add Composio to reach Gmail, Slack, Notion, Linear and more. It's off until you switch it on, and those sign-ins live on Composio's servers, not in kwant's vault.

  • A shared browser

    Bots browse in kwant's own browser profile, or in a container in VM mode.

  • Your data, one folder

    Chats, bots and settings live in ~/.kwnt by default.
