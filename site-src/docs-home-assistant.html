Connect Home Assistant

kwant connects to Home Assistant through Home Assistant's own MCP server. Bots can then read the state of your home and switch things, and every change follows your approvals. Locks, doors, garage doors, gates and alarms always ask.

A longer walkthrough, with screenshots and notes from a live 7B local model, is in the blog: Control Home Assistant from a self-hosted AI bot.

What you need

  • Home Assistant 2025.2 or later, with its Model Context Protocol integration added. In Home Assistant, open Settings › Devices & services › Add integration and pick Model Context Protocol. Before 2026.11 it's listed as Model Context Protocol Server.
  • A long-lived access token. In Home Assistant, open your profile, then Security › Long-lived access tokens › Create token, and copy it: Home Assistant shows it once. kwant uses this token, not Home Assistant's sign-in page.
  • An address kwant can reach, the one you open Home Assistant at, such as homeassistant.local:8123, http://192.168.1.20:8123 or your https://… remote address.

Home Assistant's own setup steps, options and limits are on its Model Context Protocol page. Two of its options change what your bots get. Both are under Settings › Devices & services › Model Context Protocol › Configure (Home Assistant 2026.10 and later):

  • Expose all AI tools is on for a new setup. Then the address kwant uses (Home Assistant's Main URL, /api/mcp) also offers the Home Assistant set of tools, which can read every entity and run any action. To give bots only the devices you expose to Assist (Settings › Voice assistants › Expose), turn it off and pick only Device control (called Assist in older versions).
  • Require an administrator account is on for a new setup. Then the token has to belong to an administrator, or Home Assistant refuses it and kwant shows the token error below.

Connect in kwant

The same Connect Home Assistant sheet opens from two places:

  • The Home team. Its chat shows what the team needs. Press Connect on Connect Home Assistant, or Fix after a failed check.
  • Tools. Open Settings › This space › Apps & accounts › Advanced › Manage tools › Add server, then Home Assistant under Home. With no tool server yet, there is no Manage tools: use + Add connection › Tool server (MCP) instead. Searching for "Home Assistant" or "hass" finds it too.
FieldWhat to put there
AddressWhere you open Home Assistant. With no http:// or https://, kwant uses http://, and plain http with no port gets Home Assistant's 8123. Any path is replaced: kwant connects to <address>/api/mcp.
Access tokenThe long-lived access token. Once the address is in, Make one in Home Assistant next to the label opens your profile's Security page. kwant sends it as Authorization: Bearer <token> and keeps it masked, like every tool server secret.

Press Connect. kwant saves the server in Tools (named home-assistant, or home-assistant-2 and so on if that name is taken), checks it, and shows Connected · N actions when Home Assistant answers and lists what it can do. From the Home team, kwant gives it to the team's bots, so House can use it at once. From Tools, it's saved in Tools: start a Home team (Start a Home team, shown while you have none), or turn it on for any bot in that bot's settings.

The token field empties as soon as you press Connect. If the check fails after the save, leaving the field empty on Try again keeps the saved token, so you can fix only the address. Closing the sheet after a failed check removes the server it just saved, so nothing broken stays in Tools.

The Home team

New team › From a template › Home makes:

  • House, the lead and only bot. It answers what's on, open or warm, turns things on and off when you ask, and names each device and the result. It never unlocks a door, opens a garage door or gate, or turns off an alarm on its own, and never changes automations, scenes or schedules.
  • Check the house, House's skill: one short list of what's on, open or running.
  • Lights out, a routine every day at 22:00 that turns off the lights still on and says which. It's off until you turn it on.

The team needs Home Assistant. A local model is optional, to keep what happens at home on your own computer.

What asks and what doesn't

Home Assistant's tools follow the bot's approval mode, with one rule on top:

  • Reads. Under Ask only when risky, tools Home Assistant marks read-only, like looking at the live state of your home, run without a card. Under Ask before running commands, they ask like every tool.
  • Switching things (lights, heating, blinds, media) asks or runs as your approval mode says. Always allow on such a card lets that bot run that tool without a card in that conversation only, and it still holds after kwant restarts. Bot settings › Approvals › Allowed without asking lists these, with Take back on each, and Take back all when there are two or more.
  • Locks, doors, garage doors, gates and alarms always ask, in every mode, approvals off included. A call counts when its arguments name the lock or alarm_control_panel domain or a cover that is a garage, door or gate (or doesn't say), or contain the word lock, unlock, door, garage, gate, alarm or disarm. The card says "Locks, doors, garage doors, gates and alarms always ask. Always allow isn’t offered for them." Allowing it covers that one call.
kwant applies the lock rule to any server that calls itself home-assistant when it connects, and to a server it hasn't heard from yet, never by its address.

Tested

kwant was tested against its own Home Assistant-shaped test server, not against every Home Assistant setup.
